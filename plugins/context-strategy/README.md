# 上下文策略

决定**哪些未读消息触发回复、哪些只当背景**。

---

## 解决什么问题

群里积压十几条消息时，机器人的表现经常是「听不懂在说什么」。

**根因**（不是模型笨）：

```
1. 内核把「全部未读」取走当作触发批
2. 而这些消息会被**整体排除出【过去状态】**
3. 于是模型看到的是一堆孤立的「本次唤醒」+ 一段不连贯的历史
```

十几条消息被切成碎片，上下文自然断了。

**本插件的做法**：只有「确实该回」的消息才算触发，**其余留在过去状态里当背景** ——
模型能顺着读下来，理解大家在聊什么。

---

## 三种分流模式

| 模式 | 行为 | 适合 |
|:--|:--|:--|
| **只回指向我的**（推荐） | @我 / 引用我 / 拍我 / 命中关键词才算触发，其余当背景 | 活跃群，避免抢话 |
| **指向我的优先，没有则回最后一条** | 同上，但一条都没命中时回最近一条 | 想让机器人偶尔主动开口 |
| **全部算触发**（内核默认） | 等于不启用本插件 | 对比 / 临时关闭 |

切换模式：插件页 → 上下文策略 → 配置。

---

## 额外关键字

除了 @/引用/拍一拍，还可以让某些词也触发回复：

```
小鲸鱼, 机器人, 助手
```

逗号分隔。适合「大家习惯用外号叫你」的场景。

---

## 安全设计

**内核有熔断**：本插件抛错、或返回非法值时，
内核查会自动回退到默认行为（全部算触发）—— **机器人不会因此不吭声**。

即使插件写崩了，最坏结果也只是回到「没装插件」的状态。

---

## 效果对比

假设群里连发 5 条，只有第 3 条 @ 了你：

**不用本插件**
```
【过去状态】(空，全被排除了)
【本次唤醒】1. 今天天气不错
           2. 是啊，适合出去玩
           3. @你 你觉得呢？
           4. 我先吃饭了
           5. 哈哈哈
```
模型：一堆孤立的话，看不出前因后果。

**用本插件**
```
【过去状态】1. 今天天气不错
           2. 是啊，适合出去玩
           4. 我先吃饭了
           5. 哈哈哈
【本次唤醒】3. @你 你觉得呢？
```
模型：知道大家在聊天气、有人去吃饭了，然后有人问我的看法 —— 能接得上。

## 配置项

| 字段 | 说明 |
|:--|:--|
| `mode` | `mention-only` / `mention-fallback` / `all` |
| `customKeywords` | 额外触发关键词数组 |
| `maxBackground` | 背景消息最多保留几条（默认 50） |
| `debug` | 日志里打印分流结果 |

---

## 要求

- 内核 **3.1.0+**（需要 `ctx.context.registerStrategy` API）
- 老内核装上也安全：插件会检测 API 不存在，打一条日志后静默退出
